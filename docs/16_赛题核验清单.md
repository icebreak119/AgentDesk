# AgentDesk 赛题核验清单

> 用于初赛评审快速核验。状态只标记当前仓库可复现的事实；企业微信、官方 AgentTeams 运行时、完整 RAG 和 Trace Web UI 均不冒充已完成能力。

## 1. 多 Agent 协同

| 技术要求 | 当前证据 | 核验方式 |
|---|---|---|
| 至少 3 个不同职能 Agent | 6 个身份：DutyManager、SessionTL、ChannelIngress、TriageGuard、ActVerify、CaseLearning | `docs/03_Agent_Identity清单.md` |
| AgentTeams 作为设计基点 | Manager → Team Leader → Worker 映射、职责边界、状态机和上下文映射 | `docs/03_Agent_Identity清单.md`、`orchestrator/README.md` |
| 任务拆解和上下文传递 | `DutyManager.create_task` 建立 `TaskContext`，SessionTL 传递中间结论 | `orchestrator/models/task_context.py`、`orchestrator/agents/session_tl.py` |
| 协同执行和状态追踪 | `pending → triaging → deduplicated 或 planning → acting → verifying → confirming → done/awaiting_customer_confirmation/failed/escalated` | `python -m orchestrator.demo.script_c_multichannel_case` |

## 2. 智能客服自主闭环

| 闭环环节 | Agent / Skill | 当前证据 |
|---|---|---|
| 会话输入与归一 | ChannelIngress / SessionNormalize | 统一 `SessionEvent`、`dedupe_key`；抖音 Runtime 可运行 |
| 跨渠道聚合与去重 | ChannelIngress / ConversationLedger | 匿名客户 + 归一内容 + 5 分钟窗口；剧本 C 的企微仅为离线统一契约 |
| 意图识别与分级 | TriageGuard / IntentTriage | 咨询和退款样例；低置信度/高风险升级口径 |
| 方案生成 | TriageGuard / ReplyPlan | 低风险回复草案；高风险只生成升级草案，不含执行令牌 |
| 执行与核验 | ActVerify / ChannelSend / OutcomeVerify | mock 可一键复现；抖音 Runtime 提供可选 `--live` 工具层 |
| 客户确认 | ActVerify / CustomerConfirm | `confirmed`、`needs_follow_up`、`awaiting_feedback` 分支；剧本 C 覆盖正向确认 |
| 审批、失败与审计 | DutyManager / Trace | 剧本 B 验证挂起、批准、拒绝；JSONL 记录 agent、skill、状态和输入哈希 |
| 经验沉淀 | CaseLearning / CaseDigest | 终态匿名 JSONL 档案、隐私字段断言、标签检索 `case://`；非完整 RAG |

## 3. Skill 与工具契约

| 要求 | 当前证据 |
|---|---|
| Skill 清单、输入输出、调用条件、失败处理、安全边界、复用价值 | `docs/04_Skill清单.md` 与 `skills/*/v0.1/schema.json` |
| 可运行 Skill | `SessionNormalize`、`IntentTriage`、`ReplyPlan`、`OutcomeVerify`、`CustomerConfirm`、`CaseDigest` 可由 `skills/run_skill.py` 直接调用 |
| 渠道执行 Skill | ChannelSend 由参考编排器和 `runtime/douyin/` 调用；HTTP 工具层可替换为 MCP Server |
| 等价 MCP 契约 | `docs/contracts/`：输入输出 Schema、错误码、幂等、审计和 pytest |

## 4. 上下文、可观测与安全

| 赛题建议能力 | 当前状态 | 核验方式 |
|---|---|---|
| 共享状态管理 | 可运行参考实现 | `TaskContext` JSON 往返 pytest |
| 轨迹可观测 | 可运行参考实现 | `trace.jsonl` 包含 task、agent、skill、status、输入哈希 |
| 结构化案例归档与标签检索 | 可运行参考实现 | CaseDigest 匿名 JSONL + `case://` 引用；`ReplyPlan` 接收 `knowledge_hits` |
| 知识库 RAG / 长期记忆 | 设计与复赛计划 | 当前标签检索不宣称向量 RAG；复赛建设知识治理与质量评估 |
| 权限与隔离 | 已有 Runtime 能力 | profile 隔离、`client_msg_id` 幂等、账号 scoped HTTP 接口 |
| 高风险审批与回滚 | 可运行参考编排器 | `script_b_approval` 批准/拒绝路径；未批准不发消息 |

## 5. 一键复现

```powershell
cd AgentDesk
python -m pytest -q
python -m orchestrator.demo.script_a_consult
python -m orchestrator.demo.script_b_approval
python -m orchestrator.demo.script_b_approval --reject
python -m orchestrator.demo.script_c_multichannel_case
python skills/run_skill.py intent_triage -i skills/intent_triage/v0.1/examples/refund.json --pretty
python skills/run_skill.py customer_confirm -i skills/customer_confirm/v0.1/examples/confirmed.json --pretty
python skills/run_skill.py case_digest -i skills/case_digest/v0.1/examples/confirmed_consult.json --pretty
```

预期证据：剧本 A 产生一次 ChannelSend、OutcomeVerify、CustomerConfirm 和 CaseDigest；剧本 B 产生 `approval_required` 和 `approval_granted`，拒绝路径不发送消息并以 `failed` 状态结束；剧本 C 对重复任务标记 `deduplicated`，后续任务命中 `case://` 引用。

## 6. 初赛边界

- 抖音是唯一已落地的真实渠道 Runtime；企业微信已用于统一 SessionEvent 的离线剧本，但未接入真实渠道适配器。
- `orchestrator/` 是 AgentTeams 能力映射的可运行参考实现，不声称为官方 AgentTeams 运行时。
- 初赛可验证内容是 Runtime、参考编排、Trace、Skill CLI、匿名 CaseDigest 和工具契约；生产 Task DB、完整 RAG、Trace Web UI 与官方运行时进入复赛。
