## 1. 演示目标

向评委证明三件事：

1. 场景真实：抖音私信托管是生产问题，不是概念 Demo。
2. 闭环完整：入站 → 分级 → 执行 → 核验 → 证据（设计 + 部分已落地）。
3. 工程可信：profile 隔离、防串号、核验失败可定位。

## 4. 剧本 A：普通咨询（主路径）

**输入消息：**「在吗，想了解价格」

**讲解要点：**

1. ChannelIngress 接收抖音入站消息并归一（SessionNormalize）。
2. TriageGuard 判定为 consult / low / 无需审批。
3. ReplyPlan 生成回复草案。
4. ActVerify 调用 ChannelSend 发送，并由 OutcomeVerify 校验结果。
5. 成功后沉淀执行证据（日志含 profile_id）。

**页面看什么：**

- 会话列表出现新消息
- 自动回复发出
- 日志显示发送成功（可打码账号信息）

## 5. 剧本 B：高风险审批

**输入消息：**「我要退款，帮我改一下账户」

**讲解要点：**

1. TriageGuard 标记 need_approval=true。
2. DutyManager 挂起任务，不自动执行。
3. 人工确认后，才允许 ChannelSend。
4. 拒绝则写审计日志，不发送。

**页面看什么：**

- 重要咨询 / 人工介入提示
- 未审批前不自动发送
- 审批通过或拒绝后的状态变化

## 6. 剧本 C：核验失败（加分项）

**输入消息：** 短文本如「1」「在」

**讲解要点：**

1. 不只看 preview，必须二次校验当前会话最新消息。
2. expected / actual 不一致则 verify_failed。
3. 失败不入库为成功，不自动回复。

**页面看什么：**

- 日志分支：`verify_failed` / `current_cid_mismatch` 等关键字
- 说明「发送成功 ≠ 闭环成功」

## 7. 演示总结话术（可直接念）

> AgentDesk 不是单 Bot 聊天，而是基于 AgentTeams 的多 Agent 私域客服自治工作台。  
> 初赛我们已完成抖音渠道的真实接入与发送核验能力，并给出完整的 Agent、Skill 与闭环设计。  
> 复赛将提交可执行 AgentTeams 代码包，补齐 Task Runtime、审批后端与 Trace 工作台联调。
