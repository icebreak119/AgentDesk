# AgentDesk 初赛补强计划（评委质疑项 → 可验证交付）

> 目标：在不夸大「已 Production」的前提下，补齐**可运行、可演示、可审计**的工程证据，回应多 Agent 编排 / Skill / MCP 契约三类质疑。  
> 原则：**最小可运行（MVP）> 大而全**；初赛交付物标注「参考实现 / 编排样例」，复赛再接 AgentTeams 官方运行时。

---

## 0. 问题与验收标准对照

| 评委质疑 | 初赛最低验收（必须能演示） | 不在本轮范围 |
|---|---|---|
| 无可运行多 Agent 编排 | `orchestrator/demo` 一键跑通剧本 A/B，输出 Trace JSONL | AgentTeams 官方运行时全量接入 |
| DutyManager/SessionTL 仅设计稿 | 代码中有 Manager→TL→Worker 调度与状态机跳转日志 | 分布式调度 / 高可用 |
| 无跨 Agent 调度证据 | TaskContext 在 Agent 间传递，每步写入 `trace.jsonl` | 持久化 Task DB |
| IntentTriage/ReplyPlan 无 Skill 包 | 独立目录 + `run_skill.py` 样例调用 | 生产级 LLM 微调 |
| Skill 无发布/注册机制 | `skills/registry.yaml` + 版本锁定 | 企业 Skill 市场 |
| MCP 契约不完整 | 错误码/审计/幂等规范 + `pytest` 契约校验 | 真实 MCP Server |

## 1. 总体架构（补强后）

```
AgentDesk/
├── orchestrator/              # 【新增】多 Agent 最小编排（AgentTeams 映射参考实现）
│   ├── agents/                  # DutyManager, SessionTL, Workers
│   ├── models/                  # TaskContext, TraceEvent
│   ├── demo/                    # 剧本 A/B 可执行入口
│   └── README.md
├── skills/                      # 【新增】Skill 包 + 注册表
│   ├── registry.yaml
│   ├── intent_triage/v0.1/
│   ├── reply_plan/v0.1/
│   └── run_skill.py             # CLI 样例调用
├── docs/contracts/
│   ├── common/                  # 【新增】errors / audit / idempotency
│   ├── channel.*.json           # 【增强】引用 common 规范
│   └── tests/test_contracts.py  # 【新增】可执行校验
└── runtime/douyin/              # 【已有】真实渠道工具层
```

**叙事口径（答辩必用）：**

- `orchestrator/` = **AgentTeams 分层能力的可执行参考实现**（初赛样例）
- `runtime/douyin/` = **ChannelSend / OutcomeVerify 的真实工具层**
- 二者通过 MCP 等价 HTTP 契约连接；复赛替换 orchestrator 为 AgentTeams 官方包时，**Skill 与契约无需重写**

### Phase 2 — Skill 注册与独立包（P0，1 天）

**解决：** IntentTriage / ReplyPlan 无独立包；无发布/注册机制

| 任务 | 交付物 | 验证 |
|---|---|---|
| 2.1 注册表 | `skills/registry.yaml` | ✅ 5 Skill 完整索引 |
| 2.2 IntentTriage v0.1 | `skills/intent_triage/v0.1/` | ✅ 规则引擎 + examples |
| 2.3 ReplyPlan v0.1 | `skills/reply_plan/v0.1/` | ✅ 模板回复 + examples |
| 2.4 CLI 调用 | `skills/run_skill.py` | ✅ CLI + pytest |
| 2.5 文档 | 更新 `04_Skill清单.md` 链接到 registry | ✅ |

**IntentTriage MVP 逻辑（无 LLM 依赖）：**

- 关键词规则：`退款/改账户` → `need_approval=true, risk=high`
- `价格/多少钱` → `intent=consult, priority=low`
- `confidence` 由规则命中数决定

**ReplyPlan MVP：**

- 输入 `triage_result` + `session_event`
- 输出 `draft_text` 模板（咨询/高风险不同模板）
- 高风险仅出草案，**不附带执行令牌**

**验收命令：**

```powershell
python skills/run_skill.py intent_triage -i skills/intent_triage/v0.1/examples/refund.json
python skills/run_skill.py reply_plan -i skills/reply_plan/v0.1/examples/consult.json
```

## 4. 风险与边界（答辩话术）

| 风险 | 规避 |
|---|---|
| 评委认为「参考编排 ≠ AgentTeams」 | README 明确：初赛为 **AgentTeams 能力映射的参考实现**，复赛迁移官方包 |
| mock 发送被质疑 | 提供 `--live` 模式 + 8765 真实截图；trace 中标注 `mode=mock|live` |

| 范围膨胀 | 严格不做 Trace Web UI、不做 Task DB、不做企微 |
